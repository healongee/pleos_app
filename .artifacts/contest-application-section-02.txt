02. 앱 프로젝트 소개 / 심사 자료

앱명 / 프로젝트명
Pleos RestStop — 차량 쉼터

1. 앱 한 줄 소개
주변의 주차된 차량을 휴식 공간으로 연결하고, 탑승 후 좌석별 환경을 맞춤 설정하는 차량 기반 쉼터 서비스입니다.

2. 기획 배경
이동 중 잠시 쉬고 싶어도 가까운 휴식 공간을 찾기 어렵거나, 장소까지 추가로 이동해야 하는 순간이 있습니다. 반면 주차된 차량은 온도·좌석·창문을 조절할 수 있는 개인화된 실내 공간이라는 가능성을 지닙니다. 본 프로젝트는 이 공간을 차주와 고객 간의 사전 동의·이용 요청에 기반한 단시간 쉼터로 활용하는 방안을 제안합니다. 차량 공유를 주행 수단이 아닌 ‘정차 상태의 휴식 경험’으로 확장하되, 차주의 재산 보호와 고객의 안전·사생활을 서비스 설계의 전제로 삼습니다.

3. 앱 주요 기능 및 차량 특화 요소
① 고객 모바일 웹: 카카오맵에서 주변 쉼터를 탐색하고 차량과 이용 시간을 선택해 차주에게 요청합니다. 현재 지도상의 쉼터와 좌표는 가상 시연 데이터이며, 실제 차량의 위치를 제공하지 않습니다.
② 차주 모바일 웹: 요청을 확인하고 고객에게 계좌 안내를 전달한 뒤, 외부 은행 앱에서 입금을 직접 확인하고 원격 문 열기를 승인하는 흐름을 제안합니다. 현재 구현에서는 실제 계좌·결제·은행 검증을 사용하지 않으며, 문 열기 버튼은 요청만 기록할 뿐 실제 차량 문은 열지 않습니다.
③ Pleos 차량 앱: 차량에 입실한 고객이 좌석을 선택해 자리별 열선·통풍·창문 열림 정도를 조절하고, 운전석·동승석 등받이 각도와 시트 앞뒤 위치, 구역별 목표 온도를 설정하는 인터랙티브 콘솔을 시연합니다. 현재 모든 조작과 차량 그림의 변화는 앱 내부 시뮬레이션으로, 차량 하드웨어와 연결되지 않습니다.
④ 영상·음악과 프라이버시: 주차 상태를 신뢰할 수 있게 확인하고 허용된 앱 연동이 확보되면 음악·영상 감상 경험을 검토합니다. 현재 YouTube·Netflix 버튼은 안전상 비활성화되어 있고, 앰비언트 화면은 무음 모의 화면입니다. 실내 카메라 동의 UI 역시 촬영·전송·차주 열람이 없는 로컬 시연이며, 실제 기능 도입 시 고객의 명시적·철회 가능한 동의와 상시 촬영 표시를 전제로 합니다.

4. 주요 사용 시나리오
고객이 모바일 웹에서 주변 쉼터 차량을 찾아 이용 시간을 선택하고 렌트를 요청합니다. 차주는 별도 모바일 웹에서 자신에게 온 요청을 검토하고 계좌 정보를 안내합니다. 고객은 은행 앱에서 이체하며, 차주는 실제 입금 여부를 은행 앱에서 직접 확인한 뒤 공식 권한을 갖춘 원격 제어 방식이 확보된 경우에만 문을 열어줍니다. 고객은 정차된 차량에 들어가 Pleos 차량 앱에서 자신의 좌석과 공조·창문·시트 상태를 조절하며 예약된 시간 동안 쉽니다. 종료 시 이용 상태를 정리하고 차주는 차량을 점검합니다. 현재 시연에서는 웹의 예약 상태와 차량 앱이 연결되지 않으며, 입금·문 열기·차량 제어는 실제로 실행되지 않습니다.

5. 개발 계획
현재 프로토타입은 Node.js 기반 고객·차주 모바일 웹과 Android 기반 차량 콘솔로 구성됩니다. 지도는 카카오맵 JavaScript SDK를 적용하며, 웹의 시연 요청 상태는 서버 메모리에만 저장됩니다. 차량 앱은 독립적인 오프라인 시뮬레이터로, 네 자리의 창문·열선·통풍, 앞좌석 자세 및 온도 구역 선택 UI를 구현했습니다.
실서비스 단계에서는 먼저 차량·차주 소유권 및 고객 신원을 검증하는 인증 체계, HTTPS와 영속 저장소, 계좌정보의 최소 수집·접근 통제·보관 기간을 구축하겠습니다. 다음으로 공식 Pleos Connect/차량 SDK가 제공하는 기능과 권한을 확인하고, 각 도메인의 지원 여부(capability)를 검증한 뒤 주차 상태·주행 제한에 맞춰 조작 가능한 기능만 열겠습니다. 원격 문 열기는 차량과 예약을 안전하게 결합하고 차주 재확인, 명령 유효 시간, 감사 기록 및 차량 측 성공 응답을 확보한 경우에만 도입하겠습니다. 온도·창문·좌석 기능도 차종별 지원 범위와 승객 안전 조건을 확인하며, 영상 콘텐츠는 주차 검증과 서비스 사업자의 차량용 배포·이용 정책을 충족하는 방식으로만 연동하겠습니다. 실내 카메라는 필요성과 적법성을 우선 검토하고 고객의 명시적 동의, 촬영 중 알림, 즉시 철회, 접근 기록·보관 금지 등 보호장치가 확보되지 않으면 제공하지 않겠습니다. 이 항목들은 현재 구현 완료 기능이 아닌 향후 개발 범위입니다.

6. 기대효과 및 발전 가능성
이동 중의 빈 시간을 편안한 휴식으로 전환하고, 차주에게는 안전 기준을 충족하는 범위에서 주차 차량의 새로운 활용 기회를 제공할 수 있습니다. 차량 특화 UI는 자리별 온도·시트·창문 상태를 한 화면에서 확인·조절하는 경험을 목표로 합니다. 초기 검증 대상은 이동 중 짧은 휴식이 필요한 이용자와 쉼터 운영에 동의한 차주이며, 실제 수요 검증 후 지역과 차량 모델을 단계적으로 확대하겠습니다. 서비스 지표는 월간 활성 이용자 수(MAU), 탐색→요청→실이용 전환율, 4주 재방문율(Retention), 안전·불편 신고율 등을 제안합니다. 현재 실제 이용자 데이터가 없어 예상 MAU나 Retention 수치를 사실처럼 기재하지 않으며, 파일럿 운영 이후 기준값과 목표치를 설정하겠습니다. 도입 가능성은 차량 권한·보험·책임·개인정보·운영 정책의 검증 결과에 따릅니다.
